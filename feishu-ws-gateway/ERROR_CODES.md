# 飞书网关错误码对照表

群里报错统一是这个格式，业务/管理员按代码就能判断该找谁：

```
❌ 车间订单处理失败
错误代码：GW-E1001/1107171240-3f9a
原因：服务连不上（网络不可达）
重试：自动重试 3 次仍未成功
处理建议：多半是服务正在重启，等 1 分钟重发即可
```

- **错误代码** = `码段/追溯号`
- **追溯号** = 月日时分秒（北京时间）+ 4 位随机，一次处理一个，日志里每条相关记录都带

拿到追溯号直接查日志：

```bash
docker exec feishu-ws-gateway grep '1107171240-3f9a' /app/logs/feishu_bot_ws.log
```

日志里的结构化失败行长这样，含错误码、追溯号、尝试次数、完整异常链和目标文件：

```
2026-11-07 17:12:47 [ERROR] [oc_xxx] 车间订单批量处理失败 | code=GW-E1002 | trace=1107171247-508d | attempts=4 | detail=URLError: <urlopen error [Errno 111] Connection refused> [errno=111] <- ConnectionRefusedError ... | files=['xxx.xlsx']
```

## 码段

| 码段 | 类别 | 谁的问题 |
|---|---|---|
| GW-E1xxx | 网络连接 | 服务没起来/在重启，重发大概率能好 |
| GW-E2xxx | 服务响应 | 服务接到了但报错（4xx/5xx/返回体坏了） |
| GW-E3xxx | 业务结果 | 服务正常返回但 success=False / 没产物 |
| GW-E4xxx | 飞书侧 | 下载、上传、发消息失败 |
| GW-E5xxx | 本地文件 | 待处理文件丢了/没权限 |
| GW-E9xxx | 兜底 | 未预期异常 |

## 明细

| 代码 | 含义 | 通常原因 | 群内建议 | 要不要重发 |
|---|---|---|---|---|
| GW-E1001 | 服务连不上（网络不可达，errno 101） | 适配器/服务正在重启，端口空窗 | 等 1 分钟重发 | 是（已自动重试 3 次） |
| GW-E1002 | 服务连不上（连接被拒绝，errno 111） | 服务进程没启动 | 联系管理员 | 是（已自动重试 3 次） |
| GW-E1003 | 服务连接被重置（errno 104） | 服务中途退出/重启 | 等 1 分钟重发 | 是（已自动重试 3 次） |
| GW-E1004 | 服务所在主机不可达（errno 113） | 网络/主机故障 | 联系管理员 | 是（已自动重试 3 次） |
| GW-E1005 | 处理超时 | 文件太大或服务卡住 | 先确认有没有收到结果 | **否**（服务可能仍在跑，重发会重复产出） |
| GW-E1006 | 网络异常（未分类） | DNS/代理等 | 等 1 分钟重发 | 是 |
| GW-E2001 | 服务拒绝了本次请求（HTTP 4xx） | 文件内容/参数不符合要求 | 按原因改文件 | 改完再发 |
| GW-E2002 | 服务内部报错（HTTP 5xx） | 服务侧 bug | 联系管理员 | 改完再发 |
| GW-E2003 | 服务返回内容无法解析 | 服务返回了非 JSON | 联系管理员 | 视情况 |
| GW-E3001 | 服务返回处理失败 | 单号校验、缺列等业务校验 | 按原因处理 | 改完再发 |
| GW-E3002 | 处理完成但没有生成结果文件 | 输入内容为空/全被过滤 | 确认文件内容 | 是 |
| GW-E4001 | 飞书文件下载失败 | 文件过期、权限 | 重发一次 | 是 |
| GW-E4002 | 飞书文件上传/发送失败 | 飞书接口异常、文件超限 | 重发一次 | 是 |
| GW-E5001 | 本地待处理文件读取失败 | 文件已被清理（旧批清理误删新批） | 重新发文件 | 是 |
| GW-E9001 | 未预期异常 | 代码 bug | 联系管理员 | 视情况 |

## 自动重试规则

只对 **"连不上"** 类错误重试（GW-E1001/1002/1003/1004/1006），间隔 5s → 10s → 15s，累计约 30 秒，覆盖服务重启窗口。

**HTTP 超时不重试**：超时说明请求已经进到服务里并开始处理，重试会重跑一遍、产出两份文件。

## 改动位置

- 错误码表、分类、追溯号：`src/feishu_bot_ws.py` 顶部「错误码 + 追溯号」段
- 失败出口：`_fail_from_exception()`（异常类）、`_fail_with_code()`（业务类）
- 日志时间与追溯号统一北京时间（容器 TZ 默认 UTC，代码里强制 Asia/Shanghai）
